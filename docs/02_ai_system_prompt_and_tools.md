## 1. Бұл құжаттың мақсаты

Бұл құжат AI Sales Assistant-тың "миының" нақты дизайнын сипаттайды: **system prompt** (LLM-ге берілетін нұсқау), **tool definitions** (function calling схемалары), **conversation state machine** (әңгіме барысында ақпарат қалай жиналады) және **escalation/handoff ережелері**.

Принцип: **LLM тек екі нәрсе қайтара алады — адамға арналған жауап мәтіні немесе құрал шақыруы.** Баға есептеу, дерекқорға жазу, менеджерге хабарлау — барлығы құралдар арқылы, ешқашан LLM-нің "ойынан" емес.

## 2. System Prompt

LLM әр чат-сұрауға мына prompt-пен жіберіледі. `{{...}}` бөліктері runtime-да нақты деректермен толтырылады.

```
# РОЛЬ
Сен — {{company_name}} компаниясының AI сату ассистентісің. Компания
{{city}}, Қазақстанда ас үй жиһаздары (кухни) мен гардероб/шкафтарды
өз өндірісінен жасайды және сатады.

# ТІЛ
Клиент қай тілде жазса (қазақ, орыс, ағылшын), сол тілде жауап бер.
Сөйлесу стилі: жылы, қысқа, достық — менеджер сияқты, робот емес.
Бір жауапта 2–4 сөйлемнен аспа.

# НЕГІЗГІ МАҚСАТ
Клиентті "қызығушылық" деңгейінен "дайын тапсырыс беруші" (qualified lead)
деңгейіне жеткізу: ақпарат жинау → өнім ұсыну → баға есептеу → контакт алу → lead жасау.

# АҚПАРАТ КӨЗДЕРІ (тек осыларды қолдан, ойдан шығарма)
1. Company knowledge: {{company_knowledge}}
2. Product database: search_products() / get_product() құралдары арқылы
3. Pricing rules: ешқашан баға ойдан шығарма — тек calculate_price() құралы
4. FAQ: search_faq() құралы арқылы

# ҚАТАҢ ЕРЕЖЕЛЕР (бұзуға болмайды)
1. БАҒА: ешқашан нақты баға/санды ойдан шығарма. Баға туралы сұраққа
   жауап үшін МІНДЕТТІ түрде calculate_price() шақыр. Параметрлер жеткіліксіз
   болса, алдымен сұра, содан кейін құралды шақыр.
2. ФАКТ: компания деректерінде (company knowledge, products, FAQ) жоқ
   ақпаратқа жауап берме. "Бұл туралы нақты ақпаратты менеджер береді,
   контакт қалдырыңыз" деп айт.
3. ҚАЙТАЛАМА: жиналған state-те бар ақпаратты қайта сұрама.
4. СҰРАҚ САНЫ: бір мезгілде 1 сұрақтан артық қойма. Әңгіме табиғи болсын.
5. ЭСКАЛАЦИЯ (6-бөлімді қара): триггер қосылғанда notify_manager() шақыр.
6. АДАЛДЫҚ: нақты өлшем алмайынша, барлық бағаларды "шамамен / бастапқы
   бағадан" деп қана айтуға болады.
7. РАҚЕТ: бәсекелестер туралы, нарық туралы, бізге қатысы жоқ тақырыптарға
   кірме. Жұмсақ түрде бизнеске қайтар.

# АҚПАРАТ ЖИНАУ РЕТІ (кitchen үшін)
Өлшем (метр) → стиль → бюджет → қала/аудан → материал/фасад қалауы → контакт.
(wardrobe үшін: ені → биіктігі → есік түрі → түс → бюджет → контакт.)
Клиент өзі айтып отырса — ретті бұз, қажетсіз сұрақтарды таста.

# LEAD ЖАСАУ
Контакт (ат + телефон) алынғанда және кемінде product_type + бір өлшем
немесе бюджет белгілі болса → create_lead(). Lead жасалғанын клиентке
жылы түрде айт және келесі қадамды түсіндір ("менеджер сізбен байланысады").

# SCORE (create_lead() ішінде AI өзі анықтайды)
- hot: нақты өлшем + бюджет + жақын мерзім
- warm: қызығушылық + шамамен бюджет/мерзім
- cold: жалпы қызығушылық
- unqualified: біздің бизнес аумағынан тыс

# FORMATTING
- Жауапта markdown қолданба.
- Өнім ұсынғанда өнім карточкасын құрал нәтижесінен көрсет (атау, бағадан, фото).
- Emoji-ді аз ғана қолдан (1–2 дана).
```

> **Ескерту:** `{{company_knowledge}}` бөлімі runtime-да 01-құжаттың 2-бөлімі толтырылған соң динамиканы құралады — яғни system prompt та "hallucination-proof": онда UNKNOWN мәндер болмайды, тек расталған фактілер болады.

## 3. Tool Definitions (Function Calling)

Барлық құралдар JSON Schema түрінде LLM-ге тіркеледі. Әр құралдың **кірісі**, **шығысы** және **қолданылу шарты** төменде көрсетілген.

### 3.1 `search_products`

Клиент өнім іздесе немесе ұсыныс сұраса қолданылады.

```json
{
  "name": "search_products",
  "description": "Каталогтан өнім іздеу. Параметрлер бойынша сүзгілейді.",
  "parameters": {
    "type": "object",
    "properties": {
      "category":   {"type": "string", "enum": ["kitchen", "wardrobe"]},
      "query":      {"type": "string", "description": "Еркін мәтіндік сұраныс"},
      "style":      {"type": "string"},
      "material":   {"type": "string"},
      "max_price":  {"type": "integer", "description": "KZT"}
    },
    "required": []
  }
}
```

**Шығысы:** сәйкес өнімдер тізімі (`id, name, style, materials, price.from, photo_url`). 0 өнім болса — қайтаратын жауап: "Дәл осындай дайын үлгі жоқ, бірақ сіздің өлшемдеріңіз бойынша жасай аламыз" + lead формасына бағыттау.

### 3.2 `get_product`

Нақты өнім беті ашылғанда немесе клиент нақты өнімді сұрағанда.

```json
{
  "name": "get_product",
  "description": "Өнімнің толық ақпаратын алу",
  "parameters": {
    "type": "object",
    "properties": {
      "product_id": {"type": "string", "format": "uuid"}
    },
    "required": ["product_id"]
  }
}
```

### 3.3 `search_faq`

FAQ дерекқорында semantic-іздеу. Клиент компания, жеткізу, кепілдік, төлем туралы сұраса.

```json
{
  "name": "search_faq",
  "description": "Компанияның жиі қойылатын сұрақтарынан жауап іздеу",
  "parameters": {
    "type": "object",
    "properties": {
      "query":    {"type": "string"},
      "language": {"type": "string", "enum": ["kk", "ru"], "default": "kk"}
    },
    "required": ["query"]
  }
}
```

**Шығысы:** ең сәйкес 1–3 FAQ жұбы (сұрақ+жауап). Егер ең жоғары ұқсастық төмен болса (`similarity < 0.7`) — жауапты расталған деректерден ғана құрастыр; расталған дерек жоқ болса → human handoff ұсынысы.

### 3.4 `calculate_price` — ЕҢ МАҢЫЗДЫ ҚҰРАЛ

Клиент баға сұраса **міндетті** қолданылады. LLM-ге бұл құралды айналып өтуге болмайды.

```json
{
  "name": "calculate_price",
  "description": "Нақты бизнес формуласымен бағаны есептеу. LLM өзі есептемеуі тиіс.",
  "parameters": {
    "type": "object",
    "properties": {
      "product_type": {"type": "string", "enum": ["kitchen", "wardrobe"]},
      "params": {
        "type": "object",
        "properties": {
          "length_m":      {"type": "number"},
          "width_m":       {"type": "number"},
          "height_m":      {"type": "number"},
          "style":         {"type": "string"},
          "material":      {"type": "string"},
          "facade":        {"type": "string"},
          "countertop":    {"type": "string"},
          "door_type":     {"type": "string"},
          "sections":      {"type": "integer"},
          "addons":        {"type": "array", "items": {"type": "string"}},
          "location":      {"type": "string"}
        }
      }
    },
    "required": ["product_type", "params"]
  }
}
```

**Backend логикасы (калькулятор):** `pricing_rules` кестесінен ережелерді алады → формуланы қолданады → `estimate, breakdown, disclaimer` қайтарады. Parameter жетіспесе (мысалы кухня үшін `length_m` жоқ) — қате қайтарады, AI сол кезде клиенттен толықтыруды сұрайды.

### 3.5 `create_lead`

Lead жасау. Ақпарат жеткілікті болғанда шақырылады.

```json
{
  "name": "create_lead",
  "description": "Qualified lead жасау",
  "parameters": {
    "type": "object",
    "properties": {
      "name":        {"type": "string"},
      "phone":       {"type": "string", "pattern": "^\\+7\\d{10}$"},
      "product":     {"type": "string", "enum": ["kitchen", "wardrobe"]},
      "fields":      {"type": "object"},
      "score":       {"type": "string", "enum": ["hot", "warm", "cold", "unqualified"]},
      "score_reason":{"type": "string"}
    },
    "required": ["phone", "product", "fields", "score", "score_reason"]
  }
}
```

**Backend логикасы:** `leads` кестесіне жазу → Google Sheets-ке синхрондау → жаңа lead ID қайтару.

### 3.6 `update_lead`

Әңгіме барысында жаңа ақпарат қосылғанда (мысалы, клиент телефонды кейін айтты).

```json
{
  "name": "update_lead",
  "description": "Бар lead-ке жаңа ақпарат қосу",
  "parameters": {
    "type": "object",
    "properties": {
      "lead_id": {"type": "string"},
      "fields":  {"type": "object"}
    },
    "required": ["lead_id", "fields"]
  }
}
```

### 3.7 `notify_manager`

Human handoff құралы.

```json
{
  "name": "notify_manager",
  "description": "Менеджерге эскалация — шағым, күрделі сұрақ, клиент адамды сұрағанда",
  "parameters": {
    "type": "object",
    "properties": {
      "lead_id": {"type": "string"},
      "reason":  {"type": "string"},
      "urgent":  {"type": "boolean", "default": false}
    },
    "required": ["reason"]
  }
}
```

**Backend логикасы:** lead-ті `needs_human = true` белгілеу → Telegram/WhatsApp арқылы менеджерге хабарлама (V2) → қазіргі кезеңде lead статусын `new` + `human_reason` жазу.

## 4. Conversation State Machine

AI әр сұрауда мына **state** объектісін жаңартады (client-тің жады — `conversations.state`):

```json
{
  "product":            "kitchen",
  "size_meters":        3.5,
  "style":              "modern",
  "material":           null,
  "facade":             null,
  "countertop":         null,
  "budget_tenge":       600000,
  "location":           "Astana",
  "deadline":           null,
  "contact": {
    "name":  "Ayan",
    "phone": "+77012345678"
  },
  "lead_id":            "a1b2c3...",
  "missing_fields":     ["material", "deadline"],
  "needs_human":        false,
  "human_reason":       null
}
```

### 4.1 Әрекет алгоритмі (әр жаңа хабарламада)

```
1. Клиент хабарламасын талдау
   ↓
2. Intent анықтау: [sizing_question | price_question | faq |
                    complaint | product_interest | smalltalk]
   ↓
3. Escalation триггерлерін тексеру (6-бөлім) — қосылса → notify_manager()
   ↓
4. State-те бар ақпаратты тексеру (қайта сұрамау)
   ↓
5. Қажет болса құрал(дар)ды шақыру ( параллель: search_products + search_faq)
   ↓
6. Құрал нәтижесі + расталған knowledge негізінде жауап құрастыру
   ↓
7. Жаңа ақпарат жиналса → state жаңарту; жеткілікті болса → create_lead()
   ↓
8. Жауапты клиентке жіберу
```

## 5. Lead Qualification Checklist

Lead тексерілетін минималды талаптар (осыларсыз lead жасалмайды, алдымен ақпарат толықтырылады):

| Өнім | Минималды талаптар |
|------|--------------------|
| Kitchen | product + өлшем (метр) немесе бюджет + контакт (ат+телефон) |
| Wardrobe | product + өлшемдер (ені/биіктігі) немесе бюджет + контакт |

Толық "идеал" лид барлық полялары толған лид, бірақ AI оған мәжбүрлемейді — "идеал" мен "жарамды" лидтің айырмасын түсінеді.

## 6. Human Handoff — Escalation Триггерлері

Мына жағдайлардың **кез келгені** `notify_manager()` шақырады:

| # | Триггер | Мысал клиент хабарламасы |
|---|---------|--------------------------|
| 1 | Шағым / сынған жиһаз | "Жиһазым сынып келді" |
| 2 | Қайтарым / қайтару ақша | "Ақшамды қайтарыңыздар" |
| 3 | Заңды/төлем дауы | "Келісімшарттағы пункт дұрыс емес" |
| 4 | Дұрыс емес өлшем/айып | "Шкафым сыймай қалды" |
| 5 | Бейстандарт/күрделі сұрақ | "Сіздерде 3D дизайн қанша тұрады, күрделі пішін керек" |
| 6 | Клиент адамды тікелей сұрады | "Мен адаммен сөйлескім келеді" |
| 7 | AI-дың өзі сенімсіз | search_faq ұқсастығы < 0.7 және company knowledge-те жауап жоқ |
| 8 | FAQ-те жоқ компания мәліметі | "Цехыңызды көруге бола ма?" (егер company knowledge-те жоқ болса) |

Handoff кезінде AI: (1) клиентке менеджер байланысатынын жылы айтады, (2) WhatsApp батырмасын ұсынады, (3) бар жиналған ақпаратты менеджерге дайын етіп қалдырады — клиент ештеңені қайталамайды.

## 7. Тест сценарийлерінің күтілетін мінез-құлық картасы

Phase 6-да қолданылатын үлгілер (120 сұрақ осы үлгілерге жіктеледі):

| Сұрақ | Күтілетін әрекет | Құрал | Handoff | Hallucination қаупі |
|-------|------------------|-------|---------|---------------------|
| "Сіздерде қандай материалдар бар?" | Company knowledge/FAQ жауап | search_faq | Жоқ | Орта — тек расталған тізім |
| "3 метр кухня қанша?" | Параметр сұрау → есептеу | calculate_price() | Жоқ | Жоғары — құралсыз жауап беру = FAIL |
| "Жеткізу қанша?" | FAQ + ереже бойынша | search_faq + calculate_price() | Жоқ | Орта |
| "Шкаф жасайсыздар ма?" | Иә + каталогқа бағыттау | search_products() | Жоқ | Төмен |
| "Кепілдік бар ма?" | FAQ жауап | search_faq | Жоқ | Орта |
| "Kaspi арқылы төлеуге бола ма?" | Company knowledge (UNKNOWN болса → менеджер) | search_faq | Мүмкін | Орта |
| "Жиһазым сынып келді." | Кешірім + эскалация + контакт сұрау | notify_manager() + create_lead() | **Иә** | Төмен |
| "Диван сатасыыздар ма?" | Жұмсақ түрде бас тарту, бағыт беру | — | Жоқ | Төмен |
| "Ертең өлшем алуға келе аласыздар ма?" (бюджет+мерзім анық) | Lead (hot) + менеджер хабарласуы | create_lead() | Мүмкін | Төмен |

## 8. Келесі қадам

Осы екі құжат (01 + 02) — MVP-ның толық архитектуралық негізі. Одан әрі:

1. **28 сұраққа жауап жинау** — 01-құжаттың 2-бөлімі толған сайын system prompt және pricing rules жаңарады.
2. **Phase 1 (UI)** — mock деректермен frontend құрамыз (бұны қазір бастауға болады).
3. **Phase 2–5** — деректер толыққан соң, құжаттағы схемалар бойынша.

Сұрақ болса немесе қандай да бір схеманы өзгерткіңіз келсе — айтсаңыз, құжатты жаңартамын.
